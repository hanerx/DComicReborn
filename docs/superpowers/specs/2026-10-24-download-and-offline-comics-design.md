# 通用下载与漫画离线阅读设计

日期：2026-10-24
状态：设计讨论后的审查稿；未实施，依赖能力尚未在本项目实机验证。

## 1. 目标与范围

用通用下载服务替换更新弹窗专用下载链路，并在其上实现漫画下载与离线阅读。包括后台通知进度、持久任务、图片缓存复用、可选完整性校验、单文件并行分块、断点续传、漫画下载管理、可选跨源聚合与透明本地读取。

下载任务、下载文件和离线目录属于本机，不接入同步服务器。漫画详情无需完整快照，但离线目录必须保存展示和阅读必需的信息。

不在本设计中承诺：系统永不终止任务、用户强制停止后立即自动运行、所有服务器支持续传、iOS 与 Android 具有相同通知形态。下载成功与安装成功是两个不同结果。

用户报告 Android 更新包安装时提示损坏，这是已发生的问题，但尚不能确定是传输不完整、包格式或签名等原因；不得把换下载器等同于已修复该问题。

## 2. 已确认的产品行为

### 2.1 设置

新增独立父开关“跨源聚合下载”，默认 false，位于实验功能设置。

父开关下新增“允许跨源复用”，保存值默认 true。父开关关闭时子项置灰并保留值。有效复用条件为 aggregateDownloads && reuseDownloadedChaptersAcrossSources。

| 聚合 | 复用 | 行为 |
| --- | --- | --- |
| 关闭 | 任意 | 按源展示；只读取本源本地章节，不显示跨源下载角标 |
| 开启 | 关闭 | 聚合下载目录和跨源下载角标；正常详情入口不使用其他源文件 |
| 开启 | 开启 | 聚合展示；正常详情入口可读取无歧义匹配的其他源完整章节 |

开关不删除文件、不改写来源、不触发重新下载。下载相关设置按本地设置处理，不同步。

### 2.2 入口

- 正常漫画详情：沿用远端目录。打开某话时优先完整本地章节，未完整下载时仍从云端获取整话。
- 下载列表：只展示已下载内容的漫画目录；进入后仅展示完整可读的本地章节，不请求远端漫画详情。
- 未完成任务另在下载管理的进行中/失败区域展示，不冒充离线可读章节。
- 从下载目录明确选择某个来源的已下载版本，直接读取该版本，不受跨源复用子开关限制。
- 下载详情聚合展示时，每话显示实际来源；同一话多个版本保留独立来源记录。

## 4. 依赖选型与准入

首选 background_downloader，替换 flutter_downloader，而不是长期维护两个并行引擎。

其他方案：继续使用 flutter_downloader 缺少已确认的现成单文件分块 API；al_downloader 是旧版 flutter_downloader 的封装，不解决核心缺口；Dio 加原生调度完全自研成本高，仅在候选依赖不能满足必要能力时重新评估。

调研时 pub.dev 返回 background_downloader 9.6.4。项目 Dart/Flutter 最低版本与其声明要求相容，Android Kotlin 版本高于上游文档最低要求；这只是声明兼容，不代表完成构建和运行验证。

锁定版本前检查该发布版本的实现及平台要求，不把 GitHub main 新接口直接当作发布版本已有能力。

必须做以下准入验证：

1. Android 真实文件单连接和分块下载，最终摘要一致。
2. 暂停、网络中断、后台运行、进程终止后恢复。
3. 原生任务完成而 Dart 回调未执行时，重启能恢复校验与业务提交。
4. 分块任务和长时间后台执行可组合，不依赖界面存活。
5. 请求头、重定向和当前漫画图片 URL 可工作。
6. Windows、macOS、iOS 各自具备所承诺的下载路径；平台后台能力差异明确展示。

实现验证后选择普通原生 DownloadTask 作为传输单元，不使用 ParallelDownloadTask：后者的子任务调度与完成转发依赖 Flutter isolate。分块父描述符持久化在本机，各 Range 子任务独立交给原生调度器；应用恢复后重放状态、合并和最终校验。Android 统一使用前台 WorkManager（priority 5、runInForeground），避开锁定版本 UIDT 的完成通知残留问题；通知权限被拒绝时明确提示能力下降，系统强制停止仍不能保证继续执行。

## 5. 分层与职责

### 5.1 通用下载服务

唯一对业务暴露的下载入口，接受下载描述，返回稳定业务任务 ID；支持查询状态、观察进度、暂停、恢复、取消及删除已完成文件。

下载描述包括 URL、必要请求头、目的文件、业务分组、可选缓存查询描述、预期长度/摘要、传输策略。引擎任务 ID 是内部映射，不作为漫画页面主键。

服务负责持久意图、调度与引擎状态对账、缓存复用、校验、提交及通知语义。它不认识漫画章节规则，不负责 APK 安装。

### 5.2 引擎适配器

封装 background_downloader 的入队、状态、进度、取消、恢复及平台配置。业务层不直接导入插件任务类型。

HTTP 传输复用插件原生能力；适配层负责 Range 探测、强 ETag 或可信摘要约束、分块描述符与安全合并。逐块检查响应状态、Content-Range、长度及资源身份；暂停仅保留已完整校验的分块，未完成分块重新请求。单连接在安全条件下按字节续传，否则从头重下。Android 与 Windows 已实测单连接、分块及完整摘要；Android 已实测暂停后进程重启、后台完成和非零 Range 续传。iOS/macOS 尚无当前环境运行证据，不把平台配置等同于验证通过。

### 5.3 缓存适配器与文件存储

缓存适配器复用阅读器已有缓存；持久文件存储负责临时文件和最终文件目录。缓存文件不是永久下载文件。

### 5.4 漫画下载服务

把选中的漫画章节展开为按页排序的下载清单，创建文件任务，汇总进度、失败和完成状态，维护离线目录。来源只负责解析远端章节和页面请求信息，不各自实现下载逻辑。

### 5.5 本地章节解析器

由 Provider 公共章节入口调用，负责本源查找、受设置约束的跨源查找及离线章节模型构造。

## 6. 任务状态、恢复和文件提交

业务状态至少区分 queued、running、paused、verifying、completed、failed、canceled；运行阶段可说明是缓存复制还是网络传输。失败记录可供界面解释的原因，不能只记录布尔值。

正常路径：持久任务意图 -> 缓存查询/网络下载 -> 临时文件 -> 校验 -> 最终文件提交 -> completed。

- 入队前先保存业务意图，避免系统已开始下载而业务没有记录。
- 所有工作脱离页面 context；全局服务启动时订阅引擎并恢复任务。
- 文件在校验前只处于临时区域；校验完成后在同一文件系统内重命名至最终路径。
- 文件提交与数据库提交不能假装是同一个原子事务：启动时修复“文件已提交但状态未提交”的中断窗口。
- 提交操作可重复执行；重复完成事件不能重复生成章节或重复触发安装。
- 引擎完成但校验未运行时保持 verifying，不开放文件。
- 系统中断任务可恢复；用户主动暂停不自动恢复，用户取消不自动重新入队。
- 清理临时文件时只处理确认不再属于活动任务的文件；删除已完成文件先撤销可读状态。
- 取消/删除与迟到的回调并发时，以持久取消状态和任务执行代次判定，旧完成事件不得复活任务。

任务意图存放本地数据库。插件数据库只负责传输事实，两者按稳定业务 ID 对账。不得仅依赖 Dart MemoryTaskQueue 或原生 holding queue 保存未执行任务。

## 7. 缓存复用

图片下载查询 DefaultCacheManager 中阅读器使用的同一资源。命中必须满足文件存在、有效期未过、请求身份兼容且是所需完整图片。

- 命中：流式复制到持久下载临时文件，复用统一校验与提交过程，不发送图片 HTTP 请求。
- 未命中/过期/复制中缓存被清理：转为正常网络下载，不报告虚假成功。
- 不移动阅读缓存，不永久引用其临时路径，不把解码后的内存图片当原始文件。
- 不擅自剥离签名参数，不把不同账户/请求头下的同 URL 默认视为同一内容。无法确认安全复用的缓存按未命中处理。
- 复制按流进行，避免整张大图或整本漫画读入内存。
- 下载完成的持久文件不再受 HTTP 缓存有效期控制；清缓存不能删除离线漫画。

缓存复制也计入完成页数。进度区分总完成量、实际网络传输量，缓存命中不能伪造网络速度。

## 8. 可选校验及更新包

通用任务支持无预期摘要、预期大小、预期 SHA-256 等校验策略。即使不启用摘要，也必须处理 HTTP/引擎失败、文件缺失及已知长度不符，不能把错误响应当作正常资源。

最终摘要对完整文件流式计算，缓存命中与分块合并文件同样执行配置的校验。摘要不符时不提交最终文件，不开放安装/阅读。

没有可信预期摘要时，自行计算摘要只能供以后检测本地变化，不能宣称已验证下载来源或内容真实性。ETag 不是密码学摘要。

更新下载作为通用服务调用方，使用 Release 的大小和 SHA-256 digest。摘要缺失时不给出“已验证”的安装入口，明确提示无法验证并提供发布页入口，不默默绕过更新包校验。

安装动作在业务 completed 后由更新模块处理。下载通知不能在引擎完成时直接打开尚未校验的 APK。已校验文件仍需正常 Android 安装权限和签名/兼容性检查；安装失败与下载失败分别展示。

迁移后移除旧下载插件依赖、旧回调注册及其专属平台配置；保留仍被新实现需要的安装权限。现存旧版下载任务不能宣称可无损迁移：切换后不信任固定 app.apk 残留文件，更新任务经新流程重新取得并校验。

## 9. 并发与断点续传

区分多文件并发和单文件分块：图片默认多文件并发，大文件可使用多个 Range 连接。全局并发、同主机并发及分块并发共同受限，不能无限相乘。

服务端不支持 Range 时降级普通传输，并向状态层反映不可续传；恢复无法安全继续时从头下载。验收包括 Range 被忽略返回 200、Content-Range 错误、资源 ETag/长度变化以及失效的临时文件。

分块必须属于同一字节表示，不拼接不同资源版本；本设计不引入跨镜像合并。请求必要 headers 与身份信息必须传到引擎，不能假定 Dio 的 cookie/interceptor 自动作用于原生下载器。

漫画清单先保存稳定 source/comic/chapter/page 身份，不只保存可能过期的 URL。恢复时若签名链接失效，需要来源重新解析请求描述；若无法在当前后台环境解析，任务明确暂停等待可用环境，而不是以 HTML 错误页完成。重新解析发现章节页清单变化时，不混用新旧页序，重新建立该章节任务。

## 10. 后台和通知

Android 活动下载显示进度通知，并支持插件可用的暂停/继续/取消操作；漫画以批次/分组汇总，避免每张图片一条通知。应用内下载管理使用同一任务事实。

通知权限拒绝时明确说明通知不可见，不声称仍有常驻通知。不同 Android 版本按平台实际允许的调度路径运行。

前台服务和 WorkManager 都不是永不被杀保证，设计依赖持久恢复而非保活承诺。通知栏继续操作重新进入统一调度准入；漫画章节的取消会原子地取消正在传输和排队中的页面，防止迟到回调重新启动任务。

iOS 上游不提供 Android 式动态进度条；桌面插件不提供移动端同等后台通知。支持应用内进度和状态，不伪造跨平台同等保活能力。

校验可能在应用进程恢复后完成；这期间文件保持不可用。是否可以在锁定版本原生完成回调环境执行校验由准入验证决定，不能依赖实验性回调一定能访问主 isolate、数据库或所有 Flutter 插件。

## 11. 漫画本地数据和聚合

持久数据：

- 漫画快照：sourceId、sourceComicId、原始标题、可选持久封面引用。
- 章节：sourceChapterId、原始章节标题、来源分组、排序值、所属漫画及清单版本。
- 页面：页序、文件引用、资源身份及任务关联。
- 可读状态：全部页面提交后才完整；封面缺失不阻止章节阅读。
- 实际来源：始终保存，不因聚合显示改写来源或文件归属。

存储身份为来源漫画与来源章节组合，不以归一化标题作主键。跨源映射只用于查询和展示，不合并覆盖源数据。

聚合复用现有漫画映射和章节规则。映射链或章节候选存在冲突时不自动复用，不仅凭标题相似判断。正篇、卷、番外等匹配不能仅比较数字。

聚合目录中同一匹配章节下可展示多个来源版本。正常详情角标区分本源完整下载、其他源完整下载和当前任务未完成；未完成不能显示“已下载”。

多个其他来源都存在唯一对应章节时，以本地完成时间最早的版本作为稳定默认，再按 sourceId/章节 ID 打破同时间并列；展示实际来源。这里选择的是多个已确认等价版本，不把同一来源中一对多章节映射歧义当作可选版本。

聚合配置改变后刷新视图及后续章节解析。已经打开的章节不在阅读中途替换版本或页序。

## 12. 公共章节读取

将 BaseComicDetailModel.getChapter 变为公共模板入口，来源实现迁移为明确的远端获取方法。读取顺序：

1. 查询请求来源、漫画和章节的完整本地版本。
2. 若父子开关均开启，查询明确映射且章节匹配无歧义的其他源完整版本。
3. 调用请求来源的远端章节实现。

不采用“先远端请求成功再 hook 替换”，否则离线不可用且仍发生不必要请求。下载服务需要获取远端清单时调用远端路径，不能递归进入本地替换逻辑。

返回模型保持阅读器已有页面契约，本地 pages 使用 ImageType.local。模型明确区分请求章节身份和实际文件来源：正常详情中的目录导航、阅读进度保持请求章节身份；显示来源及与内容有关的操作使用实际来源，不把 B 源 chapterId 写进 A 源历史。离线入口直接使用保存的实际来源身份。

本地章节打开不依赖评论请求。评论等在线操作仍是独立能力，离线时不可用；跨源复用时不得拿请求来源的章节 ID 请求另一来源评论。

完整性以整章为边界，不拼半章本地半章网络。打开前发现页面文件缺失/长度不符时撤销完整标记：正常详情入口回退远端，离线入口提示文件缺失并允许用户修复。阅读中发生文件删除也必须明确报错，不循环偷偷切源。

## 13. 仅本地存储边界

沿用项目 SQLite/DAO 模式增加下载任务与离线目录表，但不把它们纳入同步记录生成、同步导出和服务器协议。父子设置同样归为本地策略。

不得把仅本机可解析的绝对路径写入已有可同步的漫画历史或书架封面字段。离线身份可用于正常阅读历史，但下载可用性和本地文件引用不随历史同步。保存文件路径为应用管理目录下的相对引用，启动时解析根目录。

现有数据库备份功能如包含本地表，恢复后必须重新核对文件，不能仅靠数据库记录把另一台机器标为已下载。下载文件本身不因此自动进入备份或服务器同步。

## 14. 实施顺序与验收

实施分两个连续部分，不削减总体范围：先完成通用引擎并迁移更新下载，再完成漫画下载、离线阅读及聚合设置。每部分都应是可运行的实际功能，不交付空实现。

| 验收场景 | 可观察结果 |
| --- | --- |
| 应用切后台，通知权限允许 | Android 通知持续更新任务进度，可控制活动任务 |
| 进程中断再启动 | 任务意图仍在；可恢复任务恢复，主动暂停/取消不被复活 |
| 校验时进程中断 | 文件未提前开放；恢复后校验并完成提交 |
| 断网续传与分块恢复 | 文件最终 SHA-256 与服务端预期一致 |
| 服务端不支持 Range | 安全重下/单连接，不拼坏文件、不假报续传 |
| 有效缓存命中 | 图片 HTTP 请求数为零，清缓存后下载副本仍可读 |
| 摘要错误 | 状态失败，无安装入口、无完整本地章节 |
| 章节仅下载部分页面 | 正常入口读取远端整章，离线可读目录不列该章 |
| 完整下载后断网 | 下载列表可以打开漫画与章节，不获取远端详情 |
| 本源与他源都有下载 | 正常入口优先本源 |
| 聚合关闭、子项保存 true | 不聚合、不跨源读取 |
| 聚合开启、复用关闭 | 有跨源角标，但正常入口仍请求本源云端 |
| 两项开启且匹配明确 | 使用他源本地章节并显示真实来源 |
| 映射歧义 | 不自动跨源复用 |
| 文件被清理 | 完整状态失效；在线入口回退，离线入口提示缺失 |
| 查看同步数据 | 无下载任务、离线目录、本地路径或下载设置泄漏 |
| 更新包 | 校验通过后才可安装；安装结果与传输结果区分 |

永久测试覆盖状态转移、恢复、缓存失效、文件提交、匹配和设置优先级等用户可见行为。不测试源码文本或只验证转发。真实引擎用受控 HTTP 服务测试 Range、故障注入和摘要；Android 真机验证后台、通知和安装，不能以单元测试替代。
